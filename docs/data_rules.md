# 처리 규칙과 지표 정의

## 정제

1. 원본 값이 완전히 동일한 행은 1건만 유지하고 제거 이벤트를 기록합니다.
2. 앞뒤 공백을 제거하고 빈 문자열은 NULL로 해석합니다.
3. 같은 업무 키에 서로 다른 원본 행이 있으면 **모두** 격리합니다. 파일 순서를 최신 수정 순서로 간주하지 않습니다. 공백만 달라도 보수적으로 충돌로 분류할 수 있습니다.
4. email 누락은 NULL 유지, region 누락은 Unknown입니다.
5. 숫자 변환 실패를 0으로 대체하지 않습니다. 날짜/상태/음수/수량 오류도 격리합니다.
6. 같은 키의 최신값 선택에는 버전 정보가 필요하므로 이번 원천 계약에는 포함하지 않습니다.

## 매출 포함 조건

completed 주문 + 유효한 고객 + 1개 이상의 유효한 주문 상세 + 유효한 상품 + 정확히 1건의 성공 결제 + 주문 금액 = 상세 합계 = 성공 결제 금액.
실패 후 성공한 결제는 허용합니다. 성공 결제가 여러 건이면 하나를 임의로 선택하지 않습니다.
자식 행(주문 상세/결제)에 오류가 있으면 해당 주문 전체를 격리합니다. 입력 주문이 없는데 자식만 있으면 해당 order_id도 제외 주문 목록에 기록합니다.

## 지표

| 지표 | 정의 |
|---|---|
| 총매출 | 검증된 completed 주문의 order_amount 합계 |
| 주문 수 | fact_orders 행 수 |
| 평균 주문 금액 | 총매출 / 주문 수. 0건이면 계산 대상 없음 |
| 상품 매출 | 상품별 line_amount 합계 |
| duplicate_rows | 이번 실행에서 제거한 완전 중복 원본 행 수 |
| error_rows | 오류 이벤트가 있는 고유 (파일, 원본 행 위치) 수 |
| excluded_orders | 제외된 식별 가능한 order_id 개수; 원천에 없는 참조 주문 포함 |

일별 기준은 주문일이며 시작일과 종료일을 모두 포함합니다. 결제일 매출, 회계상 수익 인식, 환불/수수료/정산은 이 지표와 다릅니다.
오류 코드별 이벤트 합계는 한 행에 여러 사유가 있을 수 있으므로 error_rows와 같다고 가정하지 않습니다.

## 게시 정책

전체 스냅샷을 차원과 Fact에 MERGE하고, 이번 스냅샷에서 사라진 키는 제거합니다. 키 유일성 검증 후 실행하므로 같은 입력의 재실행에서 DW 업무 값이 유지됩니다.
참조 무결성은 애플리케이션과 SQL 검증으로 검사합니다. 동시 실행은 지원하지 않습니다.
